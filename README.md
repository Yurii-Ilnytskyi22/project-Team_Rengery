# Booksy · Rengery

Адаптивний сайт книгарні, що допомагає читачам знайти наступну книгу: переглянути добірку, вибрати категорію та дізнатися більше про видання. Створений командою **Rengery** як навчальний проєкт за спільним макетом Figma.

[Переглянути сайт](https://yurii-ilnytskyi22.github.io/project-Team_Rengery/) · [Макет Figma](https://www.figma.com/design/GSBBD7WhsjcRVjG5cNEuL7/Booksy--Copy-?node-id=5999-10563) · [Репозиторій](https://github.com/Yurii-Ilnytskyi22/project-Team_Rengery)

## Можливості

- Адаптивна навігація та мобільне меню.
- Промослайдер із пропозиціями книгарні.
- Каталог книг із категоріями, лічильником і кнопкою **Show More**.
- Модальне вікно книги з описом, ціною та вибором кількості.
- Слайдери відгуків і подій, форма реєстрації на подію.
- Інформаційний блок, контакти та карта розташування.
- Форма підписки з перевіркою email.
- Власна анімація завантаження з книгами та студентами.

> Реєстрація на події, підписка та покупки мають демонстраційний характер. Проєкт не виконує реальних платежів, не створює замовлень і не надсилає дані цих форм на сервер.

## Робота каталогу

Джерело даних: `https://books-backend-v2.b.goit.study`.

| Запит | Призначення |
| --- | --- |
| `GET /books/category-list` | Отримати список категорій |
| `GET /books/top-books` | Отримати початкову добірку книг |
| `GET /books/category?category=…` | Отримати книги вибраної категорії |
| `GET /books/{id}` | Отримати детальну інформацію про книгу |

Під час старту виконуються два запити: за категоріями та початковою добіркою. Запит окремої категорії надсилається після її вибору. **All categories** повертає збережену початкову добірку з `top-books`, а не повний каталог усіх книг сервера.

Початкова кількість карток — 10 на мобільних і планшетах та 24 на десктопах. **Show More** показує ще 4 книги з уже завантажених даних без додаткового запиту. Повтори прибираються за `_id`; різні записи API з однаковими назвою або обкладинкою можуть залишатися.

Під час завантаження категорії попередні картки зберігаються до успішної відповіді. За помилки користувач отримує повідомлення. Для деталей книги передбачено завантажувач, скасування незавершеного запиту та сповіщення про помилку.

## Локальний запуск

Потрібні Git, npm і версія Node.js, сумісна з установленим Vite. Для узгодженого середовища орієнтуйтеся на актуальну LTS-версію Node.js, яку використовує workflow проєкту. Для клонування через SSH потрібен налаштований ключ GitHub.

```bash
git clone git@github.com:Yurii-Ilnytskyi22/project-Team_Rengery.git
cd project-Team_Rengery
npm ci
npm run dev
```

Відкрийте адресу, яку Vite виведе в терміналі. Для отримання книг потрібне інтернет-з'єднання.

## Команди

| Команда | Дія |
| --- | --- |
| `npm ci` | Установити залежності відповідно до `package-lock.json` |
| `npm run dev` | Запустити сервер розробки |
| `npm run build` | Створити production-збірку в `dist/` |
| `npm run preview` | Переглянути готову збірку локально |

Перед `npm run preview` виконайте `npm run build`. Preview призначений для локальної перевірки результату збірки.

## Структура

```text
project-Team_Rengery/
├── .github/workflows/   # Автоматизація публікації
├── src/
│   ├── css/            # Спільні стилі та стилі секцій
│   ├── img/            # Зображення й SVG-спрайт
│   ├── js/             # Логіка секцій та завантажувача
│   ├── partials/       # HTML-паршали
│   ├── index.html      # Основна сторінка
│   └── main.js         # Імпорти та ініціалізація секцій
├── package.json
├── package-lock.json
└── vite.config.js
```

HTML-паршали об'єднуються під час обробки Vite через `vite-plugin-html-inject`. Функції ініціалізації секцій імпортуються в `main.js` і викликаються після завантаження DOM.

## Публікація

Workflow `.github/workflows/deploy.yml` запускається після push у `main` або вручну через GitHub Actions. Він установлює залежності через `npm ci`, збирає проєкт і публікує `dist/` на GitHub Pages.

Базовий шлях для GitHub Pages визначається у `vite.config.js` зі змінної `GITHUB_REPOSITORY`. Локально використовується `/`.

## Про проєкт

Booksy створено для практики командної розробки: роботи з API, адаптивної верстки, модульного JavaScript, Git та інтеграції незалежних секцій. В основі використано навчальний шаблон Web Team Project Template; поточні можливості реалізовані командою Rengery.
